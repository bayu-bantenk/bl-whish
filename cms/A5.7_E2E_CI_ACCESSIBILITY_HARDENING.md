## 4. E2E architecture

```text
npm run e2e:build    e2e/scripts/build-e2e.mjs: copy e2e/app-routes → src/app/(dashboard)/dashboard/e2e,
                     next build, remove the copy + stale .next/types/validator.ts (finally)
npm run test:e2e     playwright test  (playwright.config.ts)
  webServer 1: node e2e/mock/mock-backend.mjs        gateway :18190, storage :18195   (TEST_ADAPTER)
  webServer 2: node e2e/servers/start-app.mjs        next start :19190 → API_HOST=http://127.0.0.1:18190
                 (refuses any non-loopback backend; KONG_API_KEY empty; synthetic SESSION_SECRET;
                  server log → test-results/e2e-app.log for the leak scan)
npm run test:e2e:full   both, in order
```

- Specs are in `e2e/specs/`; support is `e2e/support/fixtures.ts` (login helper, mock control, network boundary, axe helper, secret scan).
- Workers: 1, fully serial (the mock holds shared, per-test reset state). Retries: 0.
- Shims mount the real `(dashboard)` layout, proxy, session, DAL scope, use cases, repositories and `GatewayClient`, with a FIXTURE_ONLY policy:

| User | Account | Grants |
|---|---|---|
| editor | `e2e-editor` | `content.read`, `content.create` |
| viewer | `e2e-viewer` | `content.read` |

- `content/create-ungated` renders the form without the page gate, to prove the Server Actions deny by themselves.

## 15. Flaky-test policy — applied

Retries = 0. Three flakes were **reproduced, diagnosed and fixed** (not retried):

| Flake | Root cause | Fix |
|---|---|---|
| DataTable `page.goto` "interrupted by another navigation to /dashboard/home" (1 of 3 runs) | **Product race:** after `loginAction` set the cookie, the action re-render hit the `(auth)` layout redirect **and** the client did `window.location.href` — two navigations | DECISION: `loginAction` now `redirect()`s server-side after `runAction` succeeds (one navigation); the login views no longer navigate. Unit tests updated (+1: a failed login does not redirect) |
| axe `document-title` missing (1 of 3) | The soft navigation streams `<title>` after the URL changes; the login helper returned too early | The login helper waits for the dashboard heading and `document.title` |
| axe `color-contrast` on the sheet group label (1 of 5) | axe measured mid-slide over the dimming overlay (probe: fails at ~50 ms, passes at 0 / 150 / 400 / 1000 ms; colour constant) | `expectAccessible` waits for finite animations to finish |

**After the fixes: 5 consecutive full runs, 56 / 56 each (280 executions, 0 failures), plus a final `CI=1 npm run test:e2e:full` run, 56 / 56.**

## 17. Limitations

- Everything runs against the TEST_ADAPTER backend. It proves the **architecture and UI behaviour**, not the real backend contract (A5.5R).
- The Chrome channel only; Firefox / WebKit are not run.
- The fixture list loader (`setContentServices`) is a module-level provider; E2E runs serially, so there is no cross-user mixing (RK-A55-06 still applies to copying it).
- "Too many files" is enforced by the single-file input and the one-file-per-field hook; the server cannot count files per form (intents are stateless).
- The axe checks are automated WCAG A / AA rules only; no manual screen-reader testing.

## 18. Risks

| ID | Severity | Risk |

| RK-A57-02 | High (carried) | The real backend and upload contract are unverified (A5.5R / A5.6 BLOCKED) |
| RK-A57-03 | Medium | Local runs use the installed Chrome; CI must install Chromium (`E2E_BROWSER_CHANNEL=chromium`) |
| RK-A57-04 | Medium | The login redirect behaviour changed (server-side `redirect`); legacy-parity screens (register / forgot / reset) are unaffected, but any future client code relying on `{ok:true}` from `loginAction` will not receive it |
| RK-A57-05 | Low | The `--destructive` token darkened slightly (design-system change for AA); visual review is advised |
| RK-A57-06 | Low | The E2E build writes `.next` (the dev server uses `.next/dev`; `npm run build` restores the production output) |
| RK-A57-07 | Low | The E2E ports 18190 / 18195 / 19190 must be free |
