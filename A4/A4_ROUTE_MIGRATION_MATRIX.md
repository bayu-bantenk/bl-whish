## 1. Disposition rules

| Status | Rule |
|---|---|
| **MIGRATE** | A working legacy capability. The target provides the same capability at the target route (pages) or as the feature's **Server Action / BFF data operation** (legacy datatable / options / delete / AJAX endpoints are *capabilities*, not URLs to preserve) |
| **REVIEW** | Needs a product or backend decision before migration: screens with no navigation entry (A1-F05 → OD-07), static mockups (OD-08), broken or unreachable destructive actions (OD-09), missing views whose capability exists elsewhere |
| **DEFER** | Not used. No route met "migrate later" without a decision; those items are REVIEW |
| **REMOVE** | No legacy behavior to migrate: `Route.resource`-generated routes whose controller action does not exist (97); explicit routes with missing actions (3); duplicate registrations shadowed by an identical earlier route (18); dead helpers (2) |
| **UNKNOWN** | Not used |

**Column meanings:**
- **Auth:** `PUBLIC` or `SESSION` (target authenticated).
- **Permission:** the target capability is not yet defined (OD-05). Legacy backend authorization is `UNKNOWN — BACKEND CONTRACT` (A2 §14). The legacy **menu visibility** of the feature is shown in parentheses for evidence only, since menu ≠ authorization.
- **Target Route:** a page path, or `<base> (server action / BFF data)` for data operations.

## 4. Notes

- **Target route convention:** see `A4_TARGET_ARCHITECTURE.md` §4. Legacy URLs are not preserved. Redirects from legacy URLs: OD-26.
- **Target feature packages** follow the naming map in this table (`packages/<name>`). Shared options endpoints for catalog / tc / product-class become `reference-data` use cases (§7 of the architecture document). The upload-sign endpoint becomes the shared upload BFF handler.
- **State-changing GET routes** (`/logout`, `/gpos-brand/shipping-voucher/:id/cancel`) migrate as POST mutations (security document).
- **Wizard summary routes** (POST-rendered summaries) migrate as the review step of a client-side multi-step form (form document §6); their target is the feature's `create` / `update` route.
