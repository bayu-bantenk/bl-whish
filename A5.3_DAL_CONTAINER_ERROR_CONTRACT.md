## 1. Executive summary

**A5.3 STATUS: GO-WITH-RISKS.**

Every A5.3 exit criterion is met and verified by tests, an architecture rule suite (checked by planting violations) and a runtime run (headless Chrome → `next start` → mock gateway):

- **DAL** (`src/shared/infrastructure/dal/`, server-only) is the only way pages and Server Actions reach use cases. It resolves `cookies()` / `headers()` and returns only use cases, a token-free `RequestContext` and a logger. A client import of it **fails `next build`**.
- **Composition root** (`src/shared/infrastructure/container/`) with explicit **process** and **request** scopes. Features are composed explicitly (`composeFeatures`); there is no resolve-by-name.
- **Error contract:**
  - one `AppError` taxonomy;
  - `SerializableAppError` (kind, message, retryable, and safe metadata);
  - `ActionResult` + `runAction()` for mutations;
  - `resolvePageResult()` for pages (data / empty / forbidden / notFound / error);
  - ErrorState ≠ EmptyState components.
- **Reference fixture** (`test/fixtures/reference/`, not production) proves Page → DAL → use case → port → gateway repository → GatewayClient for all 8 outcome classes, plus 401 hand-over, mutation replay-block, 409 and 422.
- **Correlation id:** the proxy generates `x-request-id`; it is propagated to the render, all server logs and the gateway (`X-Request-Id`).
- **Measured:** a dashboard page request builds **one render scope and decrypts the session once**, even though layout, page guard and page all read it.
- **No A5.1 or A5.2 regressions** (unit and runtime).

Why "WITH-RISKS" rather than GO:
- The real backend contract is still unverified; everything was checked against the local mock gateway (OD-02/03/04/36).
- The reference feature is a test fixture, so there is no production feature using the path yet.
- The multi-instance refresh race and the other A5.1 risks carry over.

None of these blocks A5.4.

## 2. Architecture

```text
Route / Server Component (app/**/page.tsx)          Server Action ('use server')
        │ getReadServices()  ─ cached per request        │ runAction(op, fn) → getMutationServices()
        ▼                                                 ▼
 DAL  src/shared/infrastructure/dal/  (server-only: cookies(), headers(), request id)
        │   { <feature use cases>, context: RequestContext, logger }
        ▼
 Use case  packages/<f>/usecases/*.usecase.ts   Result<T, AppError>; AuthorizationContext.require()
        ▼
 Repository interface  packages/<f>/domain/*.port.ts   (business intent, no HTTP types)
        ▲ implemented by
 Gateway repository  packages/<f>/repository/*.repository.ts + dto.ts   (validate → Contract)
        ▼
 GatewayClient  shared/infrastructure/http   (A5.1: server-only, Bearer/Api-Key, refresh, retry-once, typed errors)
        ▼
 Backend gateway

 Page: resolvePageResult(result) → ok(data | empty) · forbidden (403) · notFound() · error state · A5.1 auth hand-over
 Action: ActionResult<T> = { ok: true, data } | { ok: false, error: SerializableAppError }
```

## 4. Composition root

| Dependency | Scope | Notes |
|---|---|---|
| `ServerConfig` | **process** (memoized) | runtime env, server-only |
| Base logger | **process** | `LOG_LEVEL` (default `info`); a request child carries `requestId` |
| Session sealer | **process** (per secret) | stateless crypto |
| Refresh single-flight registry | **process** (`globalThis`) | keyed by session id + refresh-token fingerprint; results kept 10 s; no current user |
| Authorization policy | **process** (`processPolicy()` = P0) | stateless; the A5.4 swap point |
| Request id, cookie jar, session manager | **request** | A5.1 session semantics unchanged; `render` vs `mutable` mode |
| Gateway client | **request**, **exactly one per scope** | bound to the scope's session manager (token source) and request id; shared by the refresher and every repository |
| Repositories, use cases | **request** | built by `composeFeatures(scope)` |
| `RequestContext` (`{ requestId, session: ClientSessionView \| null, authorization }`) | **request** (memoized per scope) | token-free |
| Session state | **session** | only the A5.1 encrypted cookie; no other store |

- API: `createRequestScope(deps)` → `composeFeatures(scope)` → `buildServices(deps)`. All dependencies are passed explicitly (`ScopeDeps`: jar, mode, requestId, config, fetchImpl, logger, flights, policy, now).
- Nothing is resolved by name.
- **Adding a feature** = one entry in `composeFeatures()` (the fixture's `composeReference` shows the exact shape).
- **No shared per-user state:** a container test proves that two scopes have different session managers, gateway clients, contexts and request ids, and that user A's context never appears in user B's.

## 5. DAL

| File | Responsibility |
|---|---|
| `dal/services.ts` | Resolves `cookies()` + `x-request-id` in parallel. `getReadServices()` is React-`cache`d per request (render mode); `getMutationServices()` is for actions. Also `getRequestContext()` / `getSessionView()`. Returns `DalServices = Features & { context, logger }`, with no session manager, gateway, repositories or tokens (test) |
| `dal/page-result.ts` | `resolvePageResult(result, { returnTo, requestId })`: ok → data (empty stays empty); Forbidden → `forbidden`; NotFound → `notFound()`; Unauthenticated → A5.1 refresh/expire hand-over; other kinds → serializable error |
| `dal/run-action.ts` | `runAction(op, fn)`: Result → ActionResult. An unexpected exception is logged (`action.unexpected`, operation + error class only) and returned as `Unknown` with the request id as reference |

- **No business logic** in the DAL: it contains no validation, no feature rules, no HTTP and no UI formatting. The only mapping is Result → PageResult / ActionResult.
- **Server-only:** every DAL module has `import 'server-only'`. A temporary client component importing `dal/services` made `next build` exit 1 ("depends on server-only … dal/services.ts [Client Component Browser]"); the probe was then removed.
- **Moved:** the A5.1 `session/dal.ts` moved into the DAL. `route-access.ts` and the (dashboard) layout now read `getRequestContext()`, and `buildNavigationView()` takes the request's `AuthorizationContext` instead of a policy + subject.
- **Auth Server Actions** use `runAction()` / `getMutationServices()`. They no longer import the container.

## 6. Error contract

Error kinds follow the A4 `AppError` names (PascalCase `kind`); these correspond one-to-one to the brief's example codes.

| Gateway / runtime condition | `AppError.kind` | `retryable` | Serializable metadata |
|---|---|---|---|
| 400 with field errors | `Validation` | no | `fieldErrors` |
| 400 with a message only | `Business` (A4 taxonomy; sanitized gateway message ≤ 200 chars) | no | — |
| 401 | `Unauthenticated` (→ A5.1 refresh / retry-once / hand-over) | no | `reason` |
| 403 | `Forbidden` | no | — |
| 404 | `NotFound` | no | — |
| 409 | `Conflict` | no | — |
| 422 | `Validation` | no | `fieldErrors` |
| 429 | `RateLimited` | yes | `retryAfterSec` |
| 500 / 502 / 503 / other 5xx (JSON or not) | `Server` | yes | `status` |
| client timeout | `Timeout` | yes | — |
| DNS / refused / reset | `Network` | yes | — |
| 2xx non-JSON / malformed success payload | `Contract` (detail stays in the server log) | no | — |
| unmapped status / unexpected exception | `Unknown` | no | `reference` |

- **Serialization** (`shared/errors/serializable-error.ts`): the output is built field by field (a test proves an `Error` object's message and stack never leak). Every browser-bound error carries `kind`, `message` (Indonesian, from the presentation mapper `user-message.ts`), `retryable`, and optionally `status`, `retryAfterSec`, `reason`, `fieldErrors` and `reference` (request id). It never carries a stack, cause, headers, raw body, Contract detail, token or cookie (tested against a 500 body containing a stack trace and SQL).
- **ERROR ≠ EMPTY ≠ NOT FOUND ≠ FORBIDDEN:**
  - `{ok:true, data:[]}` renders `EmptyState` (`data-state=empty`);
  - failures render `ErrorState` (`role=alert`, `data-error-kind`, "Coba lagi" only when retryable, reference code);
  - 403 renders `AccessDenied`;
  - 404 calls `notFound()`.

## 7. Action result

```ts
type ActionResult<T> = { ok: true; data: T } | { ok: false; error: SerializableAppError }
export async function saveX(input: unknown) {
  const parsed = parse(input)                       // explicit fields only
  if (!parsed.ok) return actionFailure(parsed.error) // Validation, fieldErrors
  return runAction('x.save', ({ x }) => x.save(parsed.value))
}
```

- Expected failures are values, never thrown.
- Unexpected exceptions are logged and returned as `Unknown` with a reference.
- **Rule:** no `redirect()` / `notFound()` inside `runAction`; navigate afterwards (as `logoutAction` does).

## 9. Performance

- **Runtime (`LOG_LEVEL=debug`), 63 requests grouped by request id:**
  - Dashboard page requests: `scopes: [mutable (proxy), render]`, `reads: [mutable, render]`. So there is **one render scope and one session decrypt per render**, although the layout, page guard and page each read the session (React `cache`).
  - Gateway calls happen only in the proxy's proactive refresh and in logout.
- **Single-flight still holds:** 5 concurrent navigations on an expiring session made 1 refresh call.
- **TTFB** for `/dashboard/home` (proxy + layout + guard + page, local, mock gateway, no data reads): min 6 ms, median 12 ms, max 13 ms (10 runs). I have no baseline to compare against, so I claim no improvement.
- **No waterfall:** the DAL reads cookies and the request id in parallel; the layout reads context + cookies in parallel (`Promise.all`). No client fetch or client cache.
- The added `debug` log lines are suppressed at the default level.
